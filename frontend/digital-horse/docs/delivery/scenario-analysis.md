## 场景 2：会议纪要 → 待办闭环（核心演示场景 1 — 亮点 1 完整闭环）

### 痛点
- 1 小时会议整理纪要需 30 分钟人工听录音
- 责任人不明确 / 截止日期口头约定易遗忘
- 跨部门跟进靠群消息刷屏，容易漏
- **亮点 1 进一步**：会议中信息密度高，4 类信息（节奏 / 转写 / 决策 / 待办）人工无法同时关注
- 会议结束后纪要往往散落在不同人的笔记中，没有结构化沉淀

### 用户故事
- **作为** 部门经理，**我想要** 会议开始前预演一遍、开会中让 4 个 Agent 协作分析、会议结束后一键生成结构化报告 + 自动派单 + PDF 导出，**以便** 全流程不需要任何人工整理

### 改造前流程（5 步 / 平均 1.5 小时）
1. 会议前：凭经验预判议题 → 2. 会议中：单一人脑记录 → 3. 会议结束：听录音整理纪要（30 min） → 4. 复制到邮件 / 钉钉群通知责任人 → 5. 自行追踪完成情况

### 改造后流程（亮点 1 端到端闭环，5 步 / 平均 5 分钟）

#### Step 1：会前预演（亮点 1 差异化）
1. 主持人打开 `/meeting/:id/rehearsal` → 4 Agent 模拟 4 位参会人预演议题
2. 系统自动识别高风险议题（预算 vs 合规），给出**就绪度圆环**评分

#### Step 2：会中实时协作（亮点 1 核心）
1. 打开 `/meeting/:id/room` → 右侧默认渲染 4 Agent 协作面板
2. 每条发言（输入或语音转写）触发 `fanoutChunk()` → 4 Agent 并行：
   -  Moderator：自动总结节奏 + 引导话题
   -  Notetaker：实时记入 Blackboard，识别风险信号
   - ️ Decision：识别决策信号（"决定 / 通过 / agreed"），写入决策区
   -  Action：识别待办（"需要 / 麻烦 / please"），自动抽取责任人 + 截止时间 + 优先级，写入待办区
3. 共享 Blackboard 实时可视化（事实 / 决策 / 待办 / 风险 / 议题 / 摘要）

#### Step 3：会后自动汇总
1. 主持人点击"结束会议" → 4 Agent 进入 `summarizing` 阶段
2. Moderator 流式生成结构化摘要（事实 N 条 / 决策 N 条 / 待办 N 条 / 风险 N 条）

#### Step 4：会后自动派单（本次新增）
1. `runClosingSummary()` 自动调用 `postMeetingService.closeMeeting()`
2. 后端 `POST /api/v1/meetings/:id/actions/dispatch` 把 Blackboard 待办转成工单
3. 系统自动指派 + 自动通知 + 5% 失败率（模拟真实场景）

#### Step 5：报告导出 + 分享（本次新增）
1. 弹出 `PostMeetingDrawer`：3 个 Tab（报告 / 派单 / 导出）
2. 一键导出 PDF（含品牌标识 + 摘要 + 决策 + 待办 + 风险 + 分页页脚）
3. 一键导出 Markdown（方便归档到知识库）
4. 分享到知识库（可选）

### 量化收益
- 纪要生成：30 min → 30 s（**提速 60×**）
- 待办完成率：估算 70% → 95%（有系统追踪）
- 会议中信息遗漏率：~40% → ~5%（4 Agent 并行捕获）
- 派单耗时：人工 30 min → 自动 1 s（**提速 1800×**）
- 演示时间：亮点 1 端到端流程 5 min 可演示完整闭环（评委可一气呵成看完）

## 场景 7：消息通知业务跳转闭环（2026-09-19 新增 · 当前 commit）

### 痛点
- 通知中心收到"任务即将到期"提醒，点击"查看任务"按钮 → 只弹 toast "查看任务"，**没有任何跳转**
- 通知中心收到"会议邀请"，点击"接受" / "婉拒" → 只弹 toast，**没有联动会议状态**
- 通知中心收到"AI 智能体有新动态"，点击"查看详情" → 没有跳到 AI 板块
- 业务方反馈：**通知是"死通知"，无法闭环**

### 用户故事
- **作为** 业务经理，**我想要** 在通知中心收到"任务即将到期"提醒后**点击通知卡片或"查看任务"按钮**，**以便** 直接跳转到 Dashboard 对应待办，并完成 / 推迟 / 查看详情

### 改造前流程（4 步 / 30 秒+ · 体验断点）
1. 收到通知"任务即将到期"
2. 点击"查看任务"按钮 → 弹 toast "查看任务"
3. 手动关掉通知
4. **手动**去 Dashboard 找对应任务

### 改造后流程（1 步 / 3 秒 · 体验连贯）
1. 收到通知"任务即将到期"
2. 点击通知卡片（或"查看任务"按钮）
3. 自动标记已读 + 跳转到 Dashboard `?highlightTodo=xxx` 高亮对应待办

### 实现要点

- `NotificationType` 新增 `'todo'` 类型（原本只有 `urgent / meeting / ai / system / risk`）
- 每条通知补 `businessRef: { type: 'todo' | 'meeting' | 'approval' | 'report' | 'news', id: string }`
- `routeByBusinessRef()` 按 type 路由：
  - `todo` → `/dashboard?highlightTodo=xxx`（Dashboard 高亮对应待办）
  - `meeting` → `/meeting/:id`
  - `approval` → `/approval?workItemId=xxx`
  - `report` → `/report?reportId=xxx`
  - `news` → `/industry-news?id=xxx`
- 整个通知卡片点击 = 标记已读 + 跳转业务单据
- action 按钮 `view` / `join` / `accept` / `decline` / `complete` 全部联通

### 量化收益
- 通知 → 业务闭环时间：30 秒 → 3 秒（**提速 10×**）
- 通知点击率：估算 30% → 70%（"可点击的通知"比"死通知"吸引力提升 2.3×）
- 用户感知："通知中心从'信息墙'变成'操作台'"
