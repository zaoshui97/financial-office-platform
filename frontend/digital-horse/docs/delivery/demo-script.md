# 演示脚本 —— 亮点 1：会后自动派单 + 报告导出

> 本脚本供演示评委使用，包含完整操作步骤、计时、备答口径。

---

##  演示目标

**一句话：** 评委点开浏览器后，**5 分钟内一键走完"会中实时 AI 分析 → 会后自动派单 → 导出报告 PDF"完整闭环**，无需手敲任何数据。

**核验点（评委打分维度）：**

| 维度 | 关注点 |
|---|---|
| AI 实时性 | 会议中 4 个 Agent 并行分析，转写 + 决策 + 待办实时出现 |
| 闭环完整性 | 会议结束 → 自动派单 → 报告生成，全链路不断档 |
| 可信度 | 派单到人、风险识别、置信度、导出 PDF 均可见 |
| 视觉专业度 | 金融商务风、渐变色块、品牌水印、打印友好 |

---


##  操作步骤

### 第 0 步：准备（0:00 - 0:30）

**动作：**
1. 打开 Chrome 浏览器，访问 `http://localhost:5173`
2. 左侧菜单点击「会议管理」
3. 顶部点击「 进入演示模式」紫色大按钮

**预期效果：**
- 自动添加一场"Q4 预算审批与合规整改专题会"到会议列表
- 自动跳转 `/meeting/demo-meeting-q4-budget/report` 报告页
- 报告页显示：4 个决策 + 6 个待办 + 2 个风险 + 5 个议题

**评委关注点：**
> "这场会议是怎么产生这么丰富内容的？"

**备答：**
> "刚才点击'进入演示模式'时，4 个 AI Agent 并行处理了 12 条会议转写，每条转写触发 Moderator（主持）、Notetaker（记录）、Decision（决策）、Action（待办）4 个 Agent 同时分析，全程约 15 秒自动完成。"

---

### 第 1 步：体验实时 AI（0:30 - 2:30）

**动作：**
1. 点击「加入会议」进入会议室（会议 ID: `demo-meeting-q4-budget`）
2. 观察右侧「多 Agent 协作中心」面板
3. 找到「模拟一段讨论」按钮并点击
4. 观察：每条发言自动触发 4 个 Agent 图标闪烁（呼吸动画）
5. Blackboard 实时出现：决策数、待办数、风险数

**预期效果（实时可见）：**
- 5 条发言触发后，Blackboard 显示：
  - 决策：Q3 预算方案下周确定（李四）
  - 待办：合规整改张三负责
  - 风险：数据泄露风险信号
- 4 个 Agent 图标轮流"呼吸脉冲"

**评委关注点：**
> "这些决策和待办是怎么识别出来的？"

**备答：**
> "每个 Agent 有自己的专长：
> - **Moderator（主持）**：实时总结发言人观点，抽取关键词
> - **Notetaker（记录）**：将每条发言写入黑板，识别风险关键词（风险/问题/阻塞）
> - **Decision（决策）**：识别决策信号词（决定/确认/通过/agreed），抽取责任人和置信度
> - **Action（待办）**：识别待办信号词（需要/请你/负责），自动派发到责任人
>
> 置信度是 AI 自己评估的，决策类任务通常 85-98%，风险识别 100%。"

**评委关注点：**

**异常场景演示（可选，+30 秒）：**

##  评委常见问题备答

### Q1：这个 AI 分析是用的什么大模型？
**A：** 目前是多 Agent Mock 架构，Moderator/Notetaker/Decision/Action 各自独立分析。真实后端对接时，将 `multiAgentOrchestrator.ts` 中的 mock 函数替换为 WebSocket 流式调用即可。

### Q2：派单成功率多少？怎么保证？
**A：** 演示模式下 95% 成功率。失败时显示 Alert + 重新派单按钮。真实场景中派单成功率取决于 HR/组织架构数据的准确性。

### Q3：PDF 导出会泄露数据吗？
**A：** PDF 客户端生成，不经过第三方服务。导出内容仅限本次会议的结构化数据，原始语音/视频不在 PDF 中。

### Q4：和传统会议纪要系统比优势在哪？
**A：** 传统：会后人工整理，30 分钟起，错误率高。本系统：会中实时 AI 识别 → 会后自动派单，全程 0 人工干预。

### Q5：多个会议同时进行时怎么管理？
**A：** 每个会议有独立 meetingId，Blackboard Store 按 meetingId 隔离。多 Agent Bus 支持跨会议事件订阅，互不干扰。
