# RAG 基线评测集

本目录保存知识库 `owner_id=3`、`knowledge_base_id=1` 的离线基线用例。用例依据 2026-09-26 数据库中的活动文档、Chunk、页码元数据和活动 Point 映射生成，不包含外部资料，也不代表法规的完整法律意见。

## 文件

- `rag_baseline_cases.json`：18 道人工标注用例及知识库快照。
- 题型分布：8 道单文档事实题、4 道跨文档综合题、2 道页码与引用准确性题、2 道无依据拒答题、2 道易混淆来源题。

## 使用约束

1. 评测时固定使用知识库 ID `1`，并记录实际检索方式、模型和配置版本。
2. 正向题的标准要点只能由 `expected_document_ids` 对应的活动 Chunk 支持；不得用模型常识补齐缺失内容。
3. `expected_page_numbers` 是允许作为直接证据的页码集合。空数组表示源文档没有可靠页码，不能虚构页码。
4. 负向题应明确表达“当前知识库没有足够依据”，不得猜测金额、事实、预测或保证性结论。
5. `notes` 中的 Chunk 编号用于人工复核，不应直接提供给模型作为答案提示。
6. 法规文本可能更新；知识库文档或活动 generation 变化后，应重新核验本基线，而不是静默沿用旧答案。

## 建议评分维度

### 文档召回

- 使用响应中的 `retrieved_contexts` 检查命中文档是否覆盖 `expected_document_ids`。
- 单文档题可按目标文档是否进入 Top-K 计分。
- 跨文档题按目标文档召回率计分，并对引入无关或混淆来源酌情扣分。

### 引用页码

- 使用响应中的 `used_citations` 评估答案实际采用引用的页码准确率。
- PDF 引用页码必须落在对应文档的 `expected_page_numbers` 中。
- 对 `citation_accuracy` 题，要求关键结论与页码逐项对应。
- 没有可靠页码的 TXT/DOCX 不因页码为空扣分，但虚构页码应扣分。

`citations` 是兼容旧客户端的字段，当前内容与 `retrieved_contexts` 完全一致；新评测不得再把该字段直接视为模型实际使用的引用。

### 内容忠实度

- 逐条比对 `gold_answer_points`，记录覆盖率。
- 命中 `forbidden_claims` 视为明显不忠实或来源混淆。
- 回答可以转述，但不得扩大适用范围、遗漏关键条件或拼接未发布/非活动版本内容。

### 拒答正确率

- `should_answer=false` 时，应明确说明资料不足，并避免给出确定性事实或建议。
- 可给出补充资料建议，但不能用一般法规替代缺失的业务事实。
- 建议分别统计正确拒答、错误作答和过度拒答。

### 延迟和模型调用次数

- 记录端到端延迟、Query Embedding 次数、Qdrant 查询次数和聊天模型调用次数。
- 同一配置下报告 P50、P95 延迟，并单列失败、超时和回退请求。
- 基线比较时应固定 Top-K、Collection、Embedding 模型与维度；任何回退都必须显式记录。

## 建议结果字段

每次运行可另存结果文件，至少记录：`case_id`、HTTP 状态、检索方式、`retrieved_contexts`、`used_citations`、回答、各评分项、总延迟、Embedding/Qdrant/聊天模型调用次数及错误摘要。旧 `citations` 仅用于兼容，不作为答案引用页码评分来源。不要把密钥、Token、完整向量或敏感日志写入评测结果。
